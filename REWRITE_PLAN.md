# Documentation Rewrite — Issue Plan

## How to use this plan (agent contract)

- One issue = one branch = one PR. The site must build cleanly on every PR.
- Work phases in order. Issues within a phase are independent unless noted.
- **Never invent a number.** If a figure can't be regenerated by a committed script, insert `<!-- TODO(regenerate): description -->` and flag in the PR. Do not fill it in.
- **Escalate to the human before publishing** if: (a) a script output contradicts a planned claim, (b) the package lacks a capability an issue requires, or (c) you feel an urge to add "applications," "use cases," or industry examples. That instinct is wrong by design.
- If time is constrained, ship the **minimal path** (see "Execution order" at the end).

## Global ground rules (apply to every issue)

**Voice**
- Keep the site's existing voice: short declarative sentences, one idea per sentence, no hedging, no marketing language. ("Average returns never enter." is the register. Match it.)
- No rhetorical questions, except quoted objections on the Objections page.

**Hard vocabulary bans** (grep every PR)
- `climate`, `carbon`, `transition`, `physical risk`, `stranded`, `sustainability`, `ESG`, `net zero`, `policy`, `regulation`, `decarbonization`
- `scenario` — use `shock`, `path`, or `state` instead
- Marketing adjectives: `powerful`, `revolutionary`, `game-changing`, `cutting-edge`, `seamless`

**Truth discipline**
- No number appears on any page unless a committed script prints it. Maintain `NUMBERS.md` (see Issue 0) as the index of every figure on the site and the script that produces it.
- Every claim is scoped. The scoping line on the Home page must not be contradicted anywhere.
- Citations allowed: Kiku (2006); Bansal & Yaron (2004); Epstein & Zin (1989); Hansen & Jagannathan (1991). No other empirical claims without a source.

**Structure**
- Jekyll + Just the Docs. Front matter: `title`, `nav_order`, `parent`, `permalink`. Keep search and "Back to top" working.
- All figures generated by committed scripts into `assets/`, with alt text.
- **Preserve unchanged:** the results table (Home), the quickstart code block, the 0.4-vs-5.3 warning, MIT license, footer behavior.

## Phase 2 — The argument

### Issue 4 — New page: "Two free numbers" (the DCF counterfactual)
**Priority:** P0 · **Effort:** L · **Depends on:** Issues 0, 2

**Context.** This page quantifies the stake. It values the model's value and growth claims the way a standard DCF would — cash flows from the model, discount rate sourced separately — and shows the premium collapses. This is the hinge of the whole site; the numbers must come from code, not assertion.

**Tasks — code first**
- [ ] Create `examples/dcf_counterfactual.py`. Using `lrr.get_table_ii_params()` and the model's value/growth/market claims, compute and print:
  - [ ] (A) DCF valuation: each claim's dividend stream discounted at the model market's expected return. Print implied log P/D and implied expected return for each claim, and the implied value-growth premium.
  - [ ] (B) CAPM valuation: simulate model returns, regress value and growth on the market, print betas (expect ratio ≈ 0.92) and the CAPM-implied premium.
  - [ ] (C) Forecast-vs-valuation: shock one claim's cash-flow loadings upward with the price of risk held fixed (DCF world) vs. in equilibrium. Print price and premium response in both worlds.
- [ ] **Honesty rule:** report exactly what the script prints. If output (A) does not show a collapsed premium, stop and escalate — do not adjust the copy to claim zero.
- [ ] Record every printed number in `NUMBERS.md`.

**Tasks — page**
- [ ] Write the page in three short sections mirroring (A), (B), (C). Use these lines verbatim where marked:

```markdown
## A. One rate for everything

Discount both claims at the market's rate: the premium prices at [N].
The data say six points.

## B. A rate fitted to the CAPM

Betas sit near one (ratio 0.92). The CAPM-fitted spread is [N].

The puzzle is not an estimate. It is structural: a DCF has no slot
where the riskiness of the cash flows enters the discount rate.

## C. A forecast is not a valuation

Shock the cash flows and hold the price of risk fixed, and you have
a forecast. In equilibrium, the same news moves both. The difference
is the premium.
```

- [ ] Link back: Home hero's first sentence links here; "Value versus growth" links here as the setup it resolves.

**Acceptance**

- [ ] Page ≤ 600 words. The sentence "A DCF has no slot…" appears.

### Issue 8 — New page: "Objections"
**Priority:** P1 · **Effort:** M · **Depends on:** Issues 3, 4, 5 (links)

**Context.** Pre-empt the five predictable objections on the page so they never come up in the room. Each entry: the objection in the reader's voice, an answer ≤ 120 words, a link to evidence.

**Tasks — content (draft answers; agent may polish to voice, not to meaning)**
- [ ] *"Epstein-Zin preferences are exotic."* → They are the minimal structure that separates risk aversion from the elasticity of intertemporal substitution. Log utility prices the value premium at exactly zero. This is an existence proof, not a truth claim — see the scoping line on Home.
- [ ] *"Consumption-based pricing failed."* → The failure was power utility pricing short-run betas (Hansen–Jagannathan 1991). Here cash flows load on the persistent component of consumption, and returns never enter estimation. Link: Measuring leverage.
- [ ] *"Firms aren't consumption claims."* → Any dividend process can be projected onto the consumption moving average; that is the entire estimation step. Link: Price your own claim.
- [ ] *"We already calibrate a discount rate."* → A calibrated level is not a cross-section. This model supplies the dispersion across claims; a single rate cannot. Link: Two free numbers.
- [ ] *"This is too academic to implement."* → Every number on this site regenerates from committed scripts. Installation to first valuation: under a minute. Link: Installation.

**Acceptance**
- [ ] Five entries; every link resolves; no entry exceeds 120 words.
