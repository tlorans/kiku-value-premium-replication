# Following Kiku’s Exact Recipe with this Package

This package is a transparent, modular implementation of the methodology in
**Dana Kiku (2006) – “Is the Value Premium a Puzzle?”**.

Kiku’s paper provides the reference way to adapt a long-run risks (LRR) model so that
it simultaneously explains **time-series** properties of the aggregate market **and** the
**cross-section** of risk premia and valuations. The six steps below are taken directly
from the paper. Each step is exposed through a clear public API so that any user can
reproduce the original results or apply the same recipe to new portfolios (industries,
climate-sorted portfolios, quality, etc.).

---

## The 6-Step Recipe → Package API

| Step | What Kiku does | Package module / function |
|------|----------------|---------------------------|
| **1** | Specify the Bansal–Yaron aggregate LRR consumption process | `params.ConsumptionParams` + `dynamics.Dynamics` |
| **2** | Introduce heterogeneous cash-flow processes (different long-run loadings) | `params.DividendParams` (`phi` = long-run leverage) |
| **3** | Calibrate cash-flow dynamics **only** to time-series moments | `calibration.calibrate_from_data` / `get_table_ii_dividends` |
| **4** | Impose Epstein–Zin preferences | `params.PreferencesParams` + `preferences.EpsteinZinPreferences` |
| **5** | Solve the model numerically (Tauchen–Hussey style) | `discretization.StateGrid` + `solver.ModelSolver` |
| **6** | Evaluate both time-series **and** cross-section | `moments.compute_asset_pricing_moments` + `analytical.solve_analytical` |

---

## Step 1 – Aggregate long-run risks consumption process

Kiku starts from the Bansal–Yaron (2004) process:

- small but highly persistent expected-growth component \(x_t\) (the long-run risk factor),
- short-run consumption shocks,
- stochastic volatility of consumption growth.

**API**

```python
from kiku_value_premium.params import get_default_params, ConsumptionParams
from kiku_value_premium.dynamics import Dynamics

params = get_default_params()          # Table II values
print(params.cons)                     # mu, rho=0.98, phi_x, sigma, nu, sigma_w

dyn = Dynamics(params, seed=42)
x, sigma2 = dyn.simulate_states(T=12*74)   # monthly states for 74 years
```

The default values match Table II of the paper exactly.

---

## Step 2 – Asset-specific heterogeneous cash-flow processes

Value and growth portfolios differ **only** in their loadings on the three risk sources.
The decisive parameter is the **long-run leverage** `phi`:

- Value: `phi = 6.2` (high exposure to the persistent component of consumption)
- Growth: `phi = 2.6` (much lower exposure)
- Market: `phi = 2.8`

**API**

```python
from kiku_value_premium.params import DividendParams, ModelParams

# Exact paper values (Table II, bottom panel)
params = get_default_params()
print(params.dividends["value"].phi)   # 6.2
print(params.dividends["growth"].phi)  # 2.6

# Or construct your own
value_div = DividendParams(mu=0.0019, phi=6.2, phi_sigma=7.4, alpha=0.15)
```

The joint process (consumption + the three dividend series) is generated by:

```python
cf = dyn.simulate_cashflows(T=12*74)
# keys: x, sigma2, dc, dd_growth, dd_value, dd_market
```

## Step 3 – Calibrate cash-flow dynamics *only* to time-series moments

**Critical discipline of the paper**: never use cross-sectional return premia in the
calibration. Only match the observed time-series properties of consumption and of the
portfolios’ cash flows (especially the differential low-frequency exposure).

**API – exact paper calibration**

```python
from kiku_value_premium.calibration import get_table_ii_dividends

dividends = get_table_ii_dividends()   # exact Table II values
```

**API – general recipe for any portfolios (industries, climate, …)**

```python
from kiku_value_premium.calibration import calibrate_from_data, estimate_long_run_leverage

# dc  : 1-d array of consumption growth (annual or monthly)
# dd  : dict of portfolio dividend-growth series (same frequency)
params_dict = calibrate_from_data(
    dc,
    {"growth": dd_growth, "value": dd_value, "industry_X": dd_x},
    frequency="annual",   # or "monthly"
    window=2,             # paper uses 2-year MA of consumption (eq. 19)
)
# Each entry is a DividendParams with estimated mu, phi (long-run leverage), alpha, phi_sigma
```

The function `estimate_long_run_leverage(dc, dd, window=2)` implements equation (19)
of the paper (OLS of dividend growth on a moving average of lagged consumption growth).

Verify the calibration against Tables III–V with:

```python
from kiku_value_premium.simulation import simulate_moments, print_moments
mom = simulate_moments(n_sims=100, years=74)
print_moments(mom)
```

## Step 4 – Epstein–Zin preferences

Agents care a great deal about long-run growth prospects and uncertainty.

**API**

```python
from kiku_value_premium.params import PreferencesParams
from kiku_value_premium.preferences import EpsteinZinPreferences

prefs = PreferencesParams(delta=0.999, gamma=10.0, psi=1.5)  # Table II
ez = EpsteinZinPreferences(prefs)
print(ez.theta)          # (1-gamma)/(1-1/psi)
m = ez.imrs(delta_c, r_c)  # log intertemporal marginal rate of substitution
```

## Step 5 – Solve the model numerically (Tauchen–Hussey style)

Kiku solves the model on a discrete state space using the quadrature method of
Tauchen & Hussey (1991). The package replicates this with a product grid over
expected growth \(x\) and variance \(\sigma^2\), plus an additional Gauss–Hermite
quadrature for the short-run innovation inside every Euler evaluation.

**API**

```python
from kiku_value_premium.solver import ModelSolver

solver = ModelSolver(
    params=params,   # ModelParams with your calibrated dividends
    n_x=30,          # paper default (reduce for speed)
    n_s=4,
    n_quad=7,        # short-run innovation quadrature
)
solver.solve()       # solves consumption claim + equity claims for all portfolios
# Results live in solver.z_c, solver.z["value"], solver.z["growth"], …
# and solver.stationary (stationary distribution of the Markov chain)
```

Optional acceleration:

```bash
pip install -e ".[fast]"   # enables Numba kernels (seconds instead of minutes)
```

## Step 6 – Evaluate both time-series and cross-section

### 6a. Analytical mechanism (fast insight into the long-run channel)

```python
from kiku_value_premium.analytical import solve_analytical, print_value_premium

sol = solve_analytical(params)
print_value_premium(sol)
# Isolates the contribution of the persistent expected-growth factor.
# With the Table II calibration the package recovers a large value–growth spread
# driven almost entirely by the difference in long-run leverage (φ_V=6.2 vs φ_G=2.6).
```

### 6b. Full numerical moments (Tables VII–X)

```python
from kiku_value_premium.moments import compute_asset_pricing_moments, print_asset_pricing_moments

moments = compute_asset_pricing_moments(solver)
print_asset_pricing_moments(moments)
```

You should recover (order of magnitude):

| Quantity                        | Paper (model) | Package |
|---------------------------------|---------------|---------|
| Value premium                   | ≈ 5.3 %       | recovered |
| E[R] Growth / Value / Market    | 6.1 / 11.4 / 7.5 % | same ranking |
| log(P/D) Growth / Value / Market| 3.65 / 3.10 / 3.24 | numerical `mean_pd` |
| CAPM β ranking                  | fails to explain the premium | model reproduces CAPM failure |

## Generalizing the recipe beyond value/growth

The same six steps apply to **any** cross-section:

1. Obtain consumption growth and the cash-flow growth series of your portfolios
   (industries, climate-exposure sorts, quality, etc.).
2. Call `calibrate_from_data(...)` → obtain portfolio-specific long-run leverages `phi`.
3. Insert the resulting `DividendParams` into a `ModelParams` object.
4. Keep the same Epstein–Zin preferences and aggregate consumption process.
5. Solve with `ModelSolver`.
6. Read off the industry / climate risk premia and valuation differentials from
   `compute_asset_pricing_moments` or the analytical solution.

See the ready-to-run examples:

- `examples/calibrate_any_portfolio.py` – synthetic illustration of the full workflow
- `examples/calibrate_from_real_data.py` – template for real data
- `examples/demo.py` – quick demonstration of the original value-premium mechanism

---

## Design principles (why the API looks the way it does)

- **Discipline of calibration** – `calibrate_from_data` never sees return premia; it only
  matches cash-flow moments (exactly as Kiku requires).
- **Modularity** – each of the six steps is a separate, well-documented module so you can
  replace only the parts you need (e.g. new climate states, different preference parameters).
- **Transparency** – the analytical solution isolates the long-run risk channel that is the
  economic heart of the paper; the numerical solver then confirms the quantitative magnitude.
- **Extensibility** – the same objects (`DividendParams`, `ModelSolver`, `compute_asset_pricing_moments`)
  work for value/growth, industries, or any other portfolios once you supply the cash-flow series.
